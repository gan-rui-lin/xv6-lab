# xv6 测试函数使用指南

## 1. 概述

本文档说明如何使用 `user/initcode.c` 中的测试函数来运行操作系统赛测试镜像中的测试套件。

## 2. 测试开关配置

在 `user/initcode.c` 文件开头，有一组宏定义用于控制测试行为：

```c
// 网络测试开关
#define TEST_UDP_HOST_ECHO 0
#define TEST_UDP_BRIDGE_HOST_ECHO 0
#define TEST_TCP_LOOPBACK 0
#define TEST_TCP_HOST_ECHO 0

// 测试组开关 - 根据需要启用/禁用
#define ENABLE_BASIC_TEST 1      // 基础系统调用测试
#define ENABLE_BUSYBOX_TEST 0    // BusyBox 工具测试
#define ENABLE_LUA_TEST 0        // Lua 解释器测试
#define ENABLE_LIBC_TEST 0       // libc 功能测试
#define ENABLE_ALL_TESTS 0       // 运行所有12组测试
```

### 2.1 配置说明

- **值为 1**: 启用该测试
- **值为 0**: 禁用该测试
- **ENABLE_ALL_TESTS**: 如果设置为 1，会覆盖其他所有开关，运行全部12组测试

### 2.2 配置示例

**示例1: 只运行 basic 测试**
```c
#define ENABLE_BASIC_TEST 1
#define ENABLE_BUSYBOX_TEST 0
#define ENABLE_LUA_TEST 0
#define ENABLE_LIBC_TEST 0
#define ENABLE_ALL_TESTS 0
```

**示例2: 运行 basic 和 busybox 测试**
```c
#define ENABLE_BASIC_TEST 1
#define ENABLE_BUSYBOX_TEST 1
#define ENABLE_LUA_TEST 0
#define ENABLE_LIBC_TEST 0
#define ENABLE_ALL_TESTS 0
```

**示例3: 运行所有测试**
```c
#define ENABLE_ALL_TESTS 1
// 其他开关将被忽略
```

## 3. 测试函数说明

### 3.1 test_basic()
运行基础系统调用测试，包括33个基本系统调用。

**测试内容**:
- fork, exec, wait, exit 等进程管理
- open, read, write, close 等文件操作
- mmap, munmap, brk 等内存管理
- pipe, dup, dup2 等进程通信

**调用方式**:
```c
test_basic();
```

**预期输出**:
```
=== Running /musl/basic_testcode.sh ===
#### OS COMP TEST GROUP START basic-musl ####
[测试程序输出...]
#### OS COMP TEST GROUP END basic-musl ####
=== /musl/basic_testcode.sh completed (status=0x0) ===
```

### 3.2 test_busybox()
运行 BusyBox 工具测试。

**测试内容**:
- 常用 Unix 命令 (ls, cat, echo, mkdir, rm 等)
- Shell 脚本执行
- 文本处理工具

**调用方式**:
```c
test_busybox();
```

### 3.3 test_lua()
运行 Lua 解释器测试。

**测试内容**:
- Lua 脚本执行能力
- Lua 标准库功能

**调用方式**:
```c
test_lua();
```

### 3.4 test_libc()
运行 libc 功能测试。

**测试内容**:
- C 标准库函数完整性
- POSIX 接口兼容性

**调用方式**:
```c
test_libc();
```

### 3.5 test_all_tests()
运行所有12组测试套件，并提供详细的测试报告。

**测试内容**:
1. basic - 基础系统调用
2. busybox - BusyBox 工具
3. lua - Lua 解释器
4. libc-test - libc 功能测试
5. iozone - IO 性能测试
6. unixbench - Unix 基准测试
7. iperf - 网络吞吐量测试
8. libcbench - libc 性能测试
9. lmbench - 延迟基准测试
10. netperf - 网络性能测试
11. cyclictest - 实时性测试
12. ltp - Linux 测试项目

**调用方式**:
```c
test_all_tests();
```

**预期输出**:
```
==========================================
   Running ALL Test Suites
==========================================

[1/12] Running test: /musl/basic_testcode.sh
------------------------------------------
#### OS COMP TEST GROUP START basic-musl ####
[测试输出...]
#### OS COMP TEST GROUP END basic-musl ####
✓ Test PASSED: /musl/basic_testcode.sh
------------------------------------------

[2/12] Running test: /musl/busybox_testcode.sh
------------------------------------------
[...]

==========================================
   Test Suite Summary
==========================================
Total:  12 tests
Passed: 10 tests
Failed: 2 tests
==========================================
```

### 3.6 run_testcode()
通用的测试脚本运行函数，可以运行任意测试脚本。

**函数签名**:
```c
void run_testcode(const char *script_name);
```

**参数**:
- `script_name`: 测试脚本的完整路径（例如 "/musl/basic_testcode.sh"）

**调用示例**:
```c
// 运行自定义测试脚本
run_testcode("/musl/my_custom_test.sh");
```

## 4. 编译和运行

### 4.1 修改配置
编辑 `user/initcode.c`，设置你想要的测试开关。

### 4.2 编译
```bash
make clean
make debug
```

### 4.3 运行
```bash
./run-sdcard-rv.sh
```

### 4.4 查看输出
测试结果会直接打印到控制台。关键标记：
- `#### OS COMP TEST GROUP START <name> ####` - 测试开始
- `#### OS COMP TEST GROUP END <name> ####` - 测试结束
- `status=0x0` - 测试成功
- `status=非0` - 测试失败

## 5. 常见问题排查

### 5.1 测试无法启动

**现象**: 没有看到测试输出
**原因**:
- 测试开关未启用
- 镜像未正确挂载

**解决方案**:
1. 检查 `user/initcode.c` 中的宏定义
2. 确认 `sdcard-rv.img` 存在
3. 检查 QEMU 启动参数

### 5.2 "Exec busybox failed" 错误

**现象**: 输出 "Exec busybox failed!" 消息
**原因**:
- 镜像中找不到 `/musl/busybox`
- EXT4 文件系统未正确挂载

**解决方案**:
1. 确认镜像文件完整
2. 检查 EXT4 文件系统挂载是否成功
3. 查看内核日志中的文件系统初始化信息

### 5.3 测试执行中断

**现象**: 测试执行到一半停止
**原因**:
- 系统调用未实现或实现有误
- 内存不足
- 页面错误

**解决方案**:
1. 查看最后一条系统调用日志
2. 检查是否有 "page fault" 消息
3. 逐个启用测试，定位问题测试组

### 5.4 测试状态非0

**现象**: `completed (status=0x1)` 或其他非0状态
**原因**:
- 测试程序执行失败
- 部分测试用例未通过

**解决方案**:
1. 查看测试输出中的具体错误信息
2. 对照测试源码分析失败原因
3. 修复相关系统调用或内核功能

## 6. 测试输出解析

### 6.1 标准测试输出格式

```
=== xv6 RISC-V Operating System ===
Initializing test environment...

=== Running /musl/basic_testcode.sh ===
#### OS COMP TEST GROUP START basic-musl ####
<测试程序输出>
#### OS COMP TEST GROUP END basic-musl ####
=== /musl/basic_testcode.sh completed (status=0x0) ===

=== All tests completed ===
Shutting down...
```

### 6.2 关键信息

- **测试标记**: `#### OS COMP TEST GROUP ... ####` 是评分系统识别的关键标记
- **状态码**: `status=0x0` 表示成功，其他值表示失败
- **系统调用跟踪**: `[TRACE] [syscall] pid=X name=Y num=Z` 显示系统调用执行情况

## 7. 高级用法

### 7.1 添加自定义测试

在 `test_all_tests()` 函数的测试列表中添加你的测试脚本：

```c
const char *test_scripts[] = {
    "/musl/basic_testcode.sh",
    "/musl/my_custom_test.sh",  // 添加自定义测试
    // ...
    NULL
};
```

### 7.2 修改测试顺序

调整 `test_scripts[]` 数组中的元素顺序即可改变测试执行顺序。

### 7.3 跳过某些测试

注释掉不想运行的测试：

```c
const char *test_scripts[] = {
    "/musl/basic_testcode.sh",
    // "/musl/busybox_testcode.sh",  // 跳过此测试
    "/musl/lua_testcode.sh",
    NULL
};
```

### 7.4 单独测试某个功能

使用 `test_()` 函数测试单个程序：

```c
// 在 main() 中添加
test_("brk");     // 测试 brk 系统调用
test_("fork");    // 测试 fork 系统调用
test_("mmap");    // 测试 mmap 系统调用
```

## 8. 调试技巧

### 8.1 启用详细日志

系统已启用的日志级别：
- `LOG_DEBUG_ENABLE`
- `LOG_INFO_ENABLE`
- `LOG_WARN_ENABLE`
- `LOG_ERROR_ENABLE`
- `LOG_TRACE_ENABLE`

这些日志会显示系统调用、内存管理、文件系统操作等详细信息。

### 8.2 使用 GDB 调试

```bash
# 启用 GDB 调试
./run-sdcard-rv.sh -d

# 在另一个终端连接 GDB
riscv64-unknown-elf-gdb kernel-qemu
(gdb) target remote :1234
(gdb) break test_basic
(gdb) continue
```

### 8.3 单步执行测试

逐个启用测试开关，从简单到复杂：

1. 先测试 basic
2. 再测试 busybox
3. 最后测试完整套件

## 9. 性能优化建议

### 9.1 并行测试（不推荐）

比赛规则要求**串行执行**测试，不要尝试并行运行多个测试。

### 9.2 减少测试时间

- 只运行必要的测试组
- 优化系统调用实现
- 使用更快的存储设备（如果支持）
