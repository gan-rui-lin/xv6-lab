## 3. 技术细节

### 3.1 之前的错误分析

#### 错误1: "applet not found"
**原因**:
- Init 进程尝试执行不存在的测试程序（mmap, munmap, fstat, dup2）
- 这些程序不在镜像中，也不是 BusyBox 的 applet

**解决方案**:
- 注释掉 `user/initcode.c` 中 89-94 行的 `test_()` 调用
- 改用测试脚本方式运行

#### 错误2: Page Fault
**原因**:
- 进程尝试运行不存在的程序导致 BusyBox 错误处理
- 内存分配失败，访问无效地址

**根本原因**:
- 测试程序调用方式不正确
- 应该使用测试脚本，而不是直接 exec 单个程序名

### 3.2 镜像内容详解

#### 3.2.1 目录结构
```
/musl/                      # musl libc 环境
├── busybox                 # BusyBox 主程序
├── lib/                    # 运行库
│   └── libc.so            # musl C 库
├── basic/                  # 33个测试程序
│   ├── brk
│   ├── fork
│   ├── mmap
│   └── ...
├── basic_testcode.sh       # basic 测试脚本
└── ...                     # 其他测试脚本
```

#### 3.2.2 测试脚本工作流程
1. 切换到测试目录 (`cd ./basic`)
2. 运行 `run-all.sh` 脚本
3. 依次执行每个测试程序
4. 收集测试结果
5. 返回并输出结束标记

#### 3.2.3 BusyBox 的作用
- **多功能工具**: 包含ls, cat, echo, sh等多个命令
- **Shell 解释器**: 执行测试脚本
- **进程启动器**: 通过 sh 启动测试程序

### 3.3 调用方式对比

#### 方式1: 错误方式（已修复）
```c
test_("mmap");  // 尝试直接 exec("mmap", ...)
```
**问题**:
- `/musl/mmap` 不存在
- BusyBox 不认识 "mmap" applet
- 导致执行失败

#### 方式2: 正确方式（当前实现）
```c
// 通过 BusyBox 执行测试脚本
char *argv[] = {"sh", "/musl/basic_testcode.sh", 0};
execve("/musl/busybox", argv, envp);
```
**优点**:
- 利用 BusyBox 的 sh applet 解析脚本
- 脚本会自动切换目录并运行测试
- 符合比赛规范的输出格式
