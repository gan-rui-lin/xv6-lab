## 一、实验基本信息
### （一）实验目的
1. 深入分析xv6操作系统的系统调用机制，理解用户态与内核态的交互原理。
2. 设计并实现完整的系统调用框架，包括分发机制、参数传递及错误处理。
3. 完成进程控制、文件操作、内存管理类基础系统调用的开发，保障系统调用安全性与稳定性。
4. 解答实验指导中的核心问题，深化对系统调用性能、安全及扩展性的理解。

### （二）实验环境
- 操作系统：xv6
- 架构：RISC-V
- 开发工具：GCC、QEMU（模拟器）、Perl（桩代码生成）、GDB（调试）

## 二、实验核心原理
### （一）系统调用完整流程
1. 用户程序调用：用户通过库函数（如write()）发起系统调用。
2. 桩代码执行：usys.S中的桩代码将系统调用号加载到a7寄存器，执行ecall指令陷入内核。
3. 特权级切换：硬件自动完成U态到S态转换，保存pc到sepc、设置scause为系统调用编码，跳转至内核陷阱处理入口。
4. 陷阱处理：内核执行uservec→usertrap流程，识别系统调用类型后调用syscall()分发函数。
5. 系统调用实现：根据系统调用号调用对应内核实现函数（如sys_write()）。
6. 返回用户态：执行usertrapret→userret流程，恢复用户态寄存器和页表，通过sret指令返回用户程序。

### （二）RISC-V系统调用关键机制
- ecall指令：触发特权级切换，从用户态进入监督态，触发内核陷阱处理。
- scause寄存器：存储陷阱原因，系统调用对应编码为8。
- sepc寄存器：保存触发ecall时的用户程序计数器（pc），用于返回用户态时恢复执行位置。
- 寄存器传递：参数通过a0-a5寄存器传递，系统调用号通过a7寄存器传递，返回值通过a0寄存器返回。

#### 2. 系统调用分发器实现
```c
void syscall_dispatch(void) {
    struct proc *p = myproc();
    int num = p->trapframe->a7;  // 从a7寄存器获取系统调用号
    int ret = -1;

    // 验证系统调用号有效性
    if (num > 0 && num < NSYSCALLS && syscall_table[num].func != NULL) {
        // 调用对应系统调用实现函数
        ret = syscall_table[num].func();
    } else {
        // 处理无效系统调用
        printf("PID %d: invalid syscall %d\n", p->pid, num);
    }

    // 保存返回值到a0寄存器
    p->trapframe->a0 = ret;
}
```

### （二）任务2：参数提取与安全检查
#### 1. 参数提取辅助函数
```c
// 从寄存器中提取整数参数（n为参数索引，0对应a0，1对应a1...）
int get_syscall_arg(int n, long *arg) {
    struct proc *p = myproc();
    uint64 *regs = (uint64*)&p->trapframe->a0;  // a0-a5寄存器存储参数

    if (n < 0 || n >= 6) {  // RISC-V最多支持6个寄存器参数
        return -1;
    }

    *arg = regs[n];
    return 0;
}

// 读取用户态字符串到内核缓冲区，防止越界
int get_user_string(const char __user *str, char *buf, int max) {
    struct proc *p = myproc();
    if (max <= 0) return -1;

    // 验证用户指针有效性并复制数据
    if (copyin(p->pagetable, buf, (uint64)str, max) < 0) {
        return -1;
    }

    // 确保字符串以'\0'终止
    buf[max-1] = '\0';
    return 0;
}

// 检查用户指针有效性（地址范围、权限）
int check_user_ptr(const void *ptr, int size) {
    struct proc *p = myproc();
    uint64 addr = (uint64)ptr;

    // 检查地址是否在用户空间（xv6用户空间地址上限为0x80000000）
    if (addr + size < addr || addr + size > 0x80000000) {
        return -1;
    }

    // 检查内存页权限（是否可读/可写）
    return walkaddr(p->pagetable, addr) == 0 ? -1 : 0;
}
```

#### 2. 文件操作类：sys_write
```c
int sys_write(void) {
    long fd, count;
    char *buf;
    struct proc *p = myproc();

    // 提取参数（fd: 文件描述符，buf: 数据缓冲区，count: 写入长度）
    if (get_syscall_arg(0, &fd) < 0 || get_syscall_arg(1, (long*)&buf) < 0 || get_syscall_arg(2, &count) < 0) {
        return -1;
    }

    // 参数有效性检查
    if (fd < 0 || fd >= NOFILE || count < 0) {
        return -1;
    }
    if (check_user_ptr(buf, count) < 0) {
        return -1;  // 无效用户指针
    }

    // 调用内核文件写入函数实现功能
    return filewrite(p->ofile[fd], buf, count);
}
```

#### 3. 内存管理类：sys_sbrk
```c
void* sys_sbrk(void) {
    long n;
    struct proc *p = myproc();
    uint64 old_heap_top = p->heap_top;

    // 提取参数（n为堆大小调整值，正数扩展，负数收缩）
    if (get_syscall_arg(0, &n) < 0) {
        return (void*)-1;
    }

    // 检查堆扩展范围合法性
    if (p->heap_top + n > p->sz) {
        // 分配新的物理内存并映射到用户页表
        if (growproc(n) < 0) {
            return (void*)-1;
        }
    }

    p->heap_top += n;
    return (void*)old_heap_top;  // 返回调整前的堆顶地址
}
```

## 四、实验关键问题解答
### （一）系统调用核心机制问题
1. 陷阱帧（trapframe）的作用：存储特权级切换时的寄存器状态（包括通用寄存器、pc、特权级状态等），实现用户态与内核态之间的上下文保存与恢复，确保系统调用执行完成后能回到用户程序断点继续执行。

2. 系统调用与中断处理的异同：
   - 相同点：均会触发特权级切换，需要保存/恢复上下文，执行内核处理逻辑。
   - 不同点：系统调用由用户程序主动执行ecall指令触发，用于请求内核服务；中断由硬件设备（如时钟、磁盘）触发，异步发生，用于处理设备事件。

3. 无法直接访问用户内存的原因：用户态内存地址经过虚拟地址映射，内核需通过用户页表进行地址转换；同时用户可能传递恶意指针（如指向内核空间的地址），直接访问会导致内核安全漏洞。

### （二）系统调用分发与参数传递问题
1. 系统调用号传递方式：用户态通过将系统调用号写入a7寄存器，陷入内核后，内核从当前进程的trapframe->a7中读取该编号。

2. 返回值存储位置：系统调用的返回值通过a0寄存器传递，内核将返回值写入trapframe->a0，返回用户态后，用户程序从a0寄存器获取结果。

3. 可变参数系统调用支持方案：通过寄存器传递前6个参数，超过6个的参数存入用户栈，内核通过copyin()从用户栈读取剩余参数；或设计参数结构体，用户传递结构体指针，内核解析结构体获取所有参数。

### （三）性能与安全问题
1. 系统调用主要开销：特权级切换（用户态↔内核态）、上下文保存与恢复、用户内存访问（copyin/copyout）、安全检查（指针验证、权限判断）。

2. 减少切换开销的优化方案：合并频繁的系统调用（如批量IO操作）、采用共享内存减少数据拷贝、优化上下文切换逻辑（减少寄存器保存数量）、使用快系统调用机制（如Linux的vsyscall）。

3. 防止系统调用滥用的措施：实现权限检查（如文件访问需验证进程是否有读/写权限）、资源限制（如限制单个进程最大打开文件数）、参数严格验证（无效指针、越界长度直接拒绝）、系统调用频率限制（防止DOS攻击）。

### （四）设计权衡与扩展性问题
1. 系统调用数量确定原则：覆盖核心功能需求（进程、文件、内存、IO等），避免冗余调用；同时控制数量，减少内核维护成本和切换开销。

2. 功能性与安全性平衡策略：基础安全检查（指针、权限、边界）默认启用，确保底线安全；针对高性能场景，提供可选的安全降级接口（需用户显式声明并承担风险）；避免过度检查导致性能损耗。

3. 添加新系统调用的流程：①在系统调用表中添加新条目（编号、实现函数、参数个数）；②实现内核态系统调用函数；③生成对应的用户态桩代码和库函数声明；④添加参数验证、权限检查逻辑；⑤编写测试用例验证功能正确性。

### （五）错误处理问题
1. 系统调用失败处理方式：返回负数值表示调用失败（如-1对应通用错误），同时通过errno机制存储详细错误码（需在进程结构体中添加errno字段）；用户程序通过检查返回值是否为负，再读取errno获取具体错误原因。

2. 详细错误信息报告方案：设计错误码表，每个错误码对应唯一错误描述；提供sys_errno()系统调用，用户程序可通过该调用获取当前进程的错误码及对应描述字符串。
