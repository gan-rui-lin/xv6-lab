# 动态链接适配报告（简版）

## 背景与目标
本次 libc-test 增加动态链接考核，`entry-dynamic.exe` 依赖解释器 `/lib/ld-musl-riscv64-sf.so.1`。镜像为 FAT32，无法提供该符号链接，需要在内核侧转发至实际存在的 `libc.so`，并补足动态链接启动所需的内核支持。

## 关键适配点
1. **ELF 解释器（PT_INTERP）支持**
   - 在 `exec` 中解析 `PT_INTERP`，加载解释器 ELF，设置入口跳转到解释器。
   - `auxv` 补齐 `AT_BASE/AT_PHDR/AT_PHNUM/AT_PHENT/AT_PAGESZ/AT_ENTRY`，确保 musl 能正确自举。

2. **解释器路径转发**
   - 当 `PT_INTERP` 为 `/lib/ld-musl-riscv64-sf.so.1` 且文件缺失时，回退到 `/libc.so`（镜像根目录）。
   - 同时保留 `/lib -> /musl/lib` 的兼容尝试，适配不同镜像结构。

3. **mprotect 支持（用于 RELRO）**
   - 实现 `sys_mprotect`，按页更新 PTE 权限位，避免 `RELRO protection failed`。

4. **musl 测试依赖的 syscall 最小桩**
   - `rt_sigtimedwait`、`kill_signal`、`prlimit64` 提供最小可用实现，避免测试框架直接失败。

5. **启动脚本兼容**
   - `initcode` 同时支持 `/musl` 与根目录两种布局，避免镜像差异导致脚本找不到。

## 当前进展
- 动态链接流程已可运行，`entry-dynamic.exe` 能通过解释器启动。
- 已能通过部分 libc-test 样例（如 argv、basename 等），剩余测试可能仍受信号/线程/文件系统语义差异影响。

## 后续建议
- 按需补齐信号相关 syscall 语义（如 `rt_sigaction`、`sigaltstack`）。
- 若测试对 `dlopen`/TLS 更严格，可补充更完整的 `mmap/mprotect` 语义与地址空间布局检查。
- 统一镜像内 `/musl` 与根目录结构，减少路径兼容分支。
