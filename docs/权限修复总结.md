# xv6 EXT4 文件权限修复总结

## 问题描述

所有测试程序无法执行，错误提示"not found"，但文件确实存在于镜像中。

## 根本原因

**xv6 的 EXT4 驱动没有正确读取和使用文件权限。**

具体问题：
1. `struct inode` 没有 `mode` 字段来存储文件权限
2. `make_inode()` 函数不读取 EXT4 文件的权限
3. `stat_to_kstat()` 只设置文件类型，不设置权限位
4. 所有文件显示为 `----------` (0000 权限)

## 修复方案

### 1. 添加 mode 字段到 inode 结构体

**文件**: `src/fs/file.h`

```c
struct inode {
  uint dev;
  uint inum;
  int ref;
  struct sleeplock lock;
  int valid;

  short type;
  short major;
  short minor;
  short nlink;
  uint mode;         // ← 新增：文件权限
  uint size;
  uint addrs[NDIRECT+1];
  uint64 ext_ino;
  uint64 ext_size;
  char ext4_path[MAXPATH];
};
```

### 2. 添加 mode 字段到 stat 结构体

**文件**: `src/fs/stat.h`

```c
struct stat {
  int dev;
  uint ino;
  short type;
  short nlink;
  uint mode;        // ← 新增：文件权限
  uint64 size;
};
```

### 3. 从 EXT4 读取权限

**文件**: `src/fs/ext4fs.c`

```c
static struct inode *make_inode(const char *path, short type, uint64 size, uint64 inum) {
  struct inode *ip = iget_pub(ext4_devno, inum ? (uint)inum : 1);
  ip->type = type;
  ip->major = EXT4_INODE_TAG;
  ip->minor = 0;
  ip->nlink = 1;
  ip->size = size > 0xFFFFFFFF ? 0xFFFFFFFF : (uint)size;
  ip->ext_size = size;
  ip->ext_ino = inum;
  safestrcpy(ip->ext4_path, path, sizeof(ip->ext4_path));

  // ← 新增：读取文件权限
  uint32_t ext_mode;
  int ret = ext4_mode_get(path, &ext_mode);
  if (ret == 0) {
    ip->mode = ext_mode & 0777;  // 只取权限位
  } else {
    ip->mode = (type == T_DIR) ? 0755 : 0755;  // 默认权限
  }

  ip->valid = 1;
  return ip;
}
```

### 4. 在 stati 中填充 mode

**文件**: `src/fs/fs.c`

```c
void stati(struct inode *ip, struct stat *st)
{
  if(ext4_mode && ip->major == EXT4_INODE_TAG){
    st->dev = ip->dev;
    st->ino = ip->ext_ino;
    st->type = ip->type;
    st->nlink = ip->nlink;
    st->mode = ip->mode;      // ← 新增
    st->size = ip->ext_size;
    return;
  }
  st->dev = ip->dev;
  st->ino = ip->inum;
  st->type = ip->type;
  st->nlink = ip->nlink;
  st->mode = 0644;            // ← 新增：FAT32 默认权限
  st->size = ip->size;
}
```

### 5. 在 stat_to_kstat 中使用权限

**文件**: `src/syscall/sysfile.c`

```c
static void stat_to_kstat(struct stat *st, struct kstat *kst)
{
  kst->st_dev = st->dev;
  kst->st_ino = st->ino;

  // ← 修改：组合文件类型和权限位
  uint file_type = (st->type == T_DIR) ? 0040000 : 0100000;
  kst->st_mode = file_type | (st->mode & 0777);  // 文件类型 | 权限位

  kst->st_nlink = st->nlink;
  // ... 其他字段
}
```

## 当前状态

### ✅ 已解决
- EXT4 文件权限正确读取
- `ls -la` 显示正确的权限
- `stat` 命令返回正确的权限

### ❌ 仍未解决
- 测试程序仍然无法执行
- `execve()` 返回 -2 (ENOENT)
- Shell 脚本报告 "./brk: not found"

## 下一步调试

需要调查为什么即使权限正确，exec 仍然失败：

1. **可能原因 1**: 动态链接器路径问题
   - 测试程序需要 `/lib/ld-musl-riscv64.so.1`
   - Exec 代码有重定向到 `/musl/lib/ld-musl-riscv64.so.1`
   - 需要验证动态链接器是否被正确加载

2. **可能原因 2**: ELF 加载问题
   - 检查 exec 代码中的 ELF 头验证
   - 检查程序段（PT_LOAD）加载
   - 检查解释器段（PT_INTERP）处理

3. **可能原因 3**: 其他权限检查
   - Exec 中可能有其他地方检查权限
   - 需要追踪 exec 的完整执行路径
