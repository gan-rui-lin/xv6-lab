## 三、面试高频问题与项目回答模板

### Q1："介绍一下你的项目"

> "我参与开发了 RUOS，一个基于 xv6 改造的 RISC-V 教学内核，目标是通过全国 OS 内核竞赛的全部测试。项目用 C 和 RISC-V 汇编实现，覆盖了 OS 五大核心模块：
> - **进程**：64 路信号 + MLFQ 四级调度 + clone 线程支持
> - **内存**：buddy+slab 物理分配 + Sv39 页表 + VMA 惰性映射 + COW
> - **文件系统**：三层 VFS（xv6fs/FAT32/ext4），FAT32 支持长文件名
> - **驱动**：VirtIO 磁盘/网卡、UART、PLIC
> - **网络**：嵌入 TCP/IP 栈 + BSD socket API
>
> 最终通过了全部 31 项基础测试，决赛现场 3 小时实现了 3 个新系统调用。"

### Q2："讲讲你遇到过最难的 bug"

> "内核运行时随机触发 store page fault，stval 是 0x3fffff8000 这种高地址。一开始以为是用户程序越界，后来发现这个地址恰好在内核栈下方的 guard page。
>
> **定位过程**：看 kernel.asm 反汇编，发现 fault 时 sp 已经低于 KSTACK 底部。追调用链发现 FAT32 路径解析 → 簇链遍历 → readi → bio → 嵌套了 6-7 层函数，每层局部变量加起来超过 4KB。
>
> **修复**：memlayout.h 中把 KSTACK_PAGES 从 1 改为 2，同时修改 proc_mapstacks 映射 2 页。这个经历让我理解了为什么 Linux 默认内核栈是 8KB（2页），以及为什么 CONFIG_KASAN 需要更大的栈。"

### Q3："你了解 Linux 内核的 xxx 吗？"（引导到你熟悉的领域）

**策略**：坦诚说 RUOS 是教学内核不是 Linux，但设计思路相通，然后引导到你熟悉的对照点：

| Linux 概念 | RUOS 对照 | 你可以说 |
|-----------|----------|---------|
| CFS 调度器 | MLFQ 调度器 | "我们实现的是 MLFQ，Linux 用的是 CFS 红黑树。我理解 CFS 的 vruntime 概念，和 MLFQ 的 boost 防饥饿思路类似" |
| slab 分配器 | slab 分配器 | "我们自己实现了 7 个 size class 的 slab，和 Linux 的 SLUB 思路一样——对象池 + bitmap 管理" |
| VFS 四对象 | if-else 分发 | "我们用全局 flag 分发到 FAT32/ext4/xv6fs，Linux 用 inode_operations/file_operations 函数指针虚表，更优雅但思路一样" |
| mmap/VMA | VMA 链表 | "我们实现了 VMA 链表 + lazy fault，Linux 用的是红黑树（maple tree），但 page fault 处理流程几乎一样" |
| virtio 驱动 | virtio_disk.c | "我实现了 VirtIO MMIO 的描述符链和 ring buffer，和 Linux virtio 子系统的 split virtqueue 完全对应" |

## 四、需要重点准备的知识缺口

按优先级排列（面试被问到的概率从高到低）：

### P0：必须补（几乎一定会问）

**1. Linux 内核基础**
- 进程调度：CFS 原理（vruntime、红黑树、nice 值），实时调度（FIFO/RR）
- 内存管理：伙伴系统、slab/slub、VMA（vm_area_struct）、缺页处理、OOM killer
- 中断：上半部/下半部（softirq、tasklet、workqueue），中断亲和性
- 同步：spinlock、mutex、RCU、完成量（completion）、原子操作
- 推荐：读 《Linux 内核设计与实现》（Robert Love）前 12 章

**2. x86 基础架构**
- 分页：CR3、四级页表（PML4→PDP→PD→PT）、PAE
- 特权级：ring 0-3、syscall/sysret、中断门/陷阱门
- 中断：IDT、APIC（Local APIC + I/O APIC）、MSI/MSI-X
- 启动：BIOS POST → UEFI DXE → OS Loader → 内核
- 推荐：读 Intel SDM Vol.3 第 2-4 章（分页和保护模式）

**3. Linux 驱动模型**
- 设备树（Device Tree）、platform_device / platform_driver
- probe/remove 生命周期
- 字符设备（cdev）、块设备、网络设备
- DMA 映射（dma_map_single、一致性 DMA）
- 中断申请（request_irq）、中断线程化
- 推荐：读 LDD3（Linux Device Drivers 第三版）前 10 章

### P1：建议补（大概率涉及）

**4. ELF 与编译链接**
- ELF 文件格式：section vs segment、program header、.text/.data/.bss/.got/.plt
- 静态链接 vs 动态链接（ld.so、GOT/PLT 延迟绑定）
- 你的项目里动态链接适配（PT_INTERP 解析）是很好的切入点

**5. UEFI/BIOS 基础概念**
- UEFI 启动阶段：SEC → PEI → DXE → BDS → OS
- ACPI 表（MADT、SRAT、MCFG）
- Secure Boot 链
- 与 SBI 的类比：SBI 是 RISC-V 的"Runtime Services"

**6. 性能分析工具**
- `perf stat`（硬件计数器）、`perf record` + `perf report`（采样分析）
- `ftrace`（函数跟踪）、`trace-cmd`
- `eBPF`/`bpftrace`（可编程跟踪）
- 火焰图（FlameGraph）

### P2：了解即可（可能聊到）

**7. RAS（可靠性/可用性/可维护性）**
- ECC 内存、内存巡检（patrol scrub）
- CPU MCA（Machine Check Architecture）、CMCI
- PCIe AER（Advanced Error Reporting）
- 热插拔（CPU/内存/PCIe）
- 你的项目中 guard page 检测栈溢出、日志事务可类比

**8. BMC 基础**
- BMC = 独立管理控制器，跑 OpenBMC 或专有固件
- IPMI 协议、Redfish API
- 带外管理（out-of-band）：远程开关机、传感器监控、SOL

**9. AI + 系统**
- GPU 驱动（NVIDIA/AMD 显卡驱动架构）
- 异构计算（CPU+GPU+DPU）
- 大模型训练对内存/网络/存储的需求
- RDMA、NVLink、CXL 等高速互连

**关键策略：用项目经历类比企业技术，展示迁移能力。**

| 你做过的 | 类比到服务器场景 | 面试话术 |
|---------|----------------|---------|
| SBI ecall 固件交互 | UEFI Runtime Services | "SBI 是 RISC-V 的固件接口，和 UEFI 的 Runtime Services 角色一样——内核通过标准接口调用固件服务，我理解这种抽象层的设计意图" |
| VirtIO 驱动开发 | Linux 设备驱动 | "VirtIO 的 descriptor + avail/used ring 就是 Linux virtio 子系统的 split virtqueue，我理解 DMA 描述符链和中断通知的工作流" |

| page fault 驱动的惰性映射 | Linux demand paging | "我们的 VMA + lazy fault 和 Linux 的 handle_mm_fault 是同一个思路，只是 Linux 多了 file page cache 和 swap" |
| 内核栈溢出调试 | 服务器 RAS 故障诊断 | "定位 guard page fault 的过程和服务器上定位 MCE（Machine Check Exception）类似——都是从异常地址反推硬件/软件状态" |
| 多核启动 (started 门控) | SMP 启动 | "我们用 volatile 变量做 hart 同步，Linux 用的是 spin-table 或 PSCI，但核心思想一样——BSP 先初始化，AP 等信号" |

| 竞赛现场 3h 实现 syscall | 快速交付能力 | "决赛限时 3 小时，我从读题到实现到调通 close_range/eventfd2/waitid，锻炼了快速理解需求和底层编码的能力" |
