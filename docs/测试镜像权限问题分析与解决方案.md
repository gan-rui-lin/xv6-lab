# 测试镜像权限问题分析与解决方案

## 问题概述

运行 basic 测试时，所有测试程序都报 "not found" 错误，但实际上文件存在于镜像中。

## 问题根源

经过深入调试，发现问题的根本原因是：**镜像中所有文件的权限都是 0000 (`----------`)**

### 验证过程

1. **文件确实存在**:
```bash
ls -la /musl/basic/
# 输出显示所有测试文件都存在
```

2. **权限检查**:
```bash
stat /musl/basic/brk
# Access: (0000/----------)  Uid: (    0/ UNKNOWN)   Gid: (    0/ UNKNOWN)
```

3. **文件可读但不可执行**:
```bash
head -c 16 /musl/basic/brk
# 成功输出 "ELF"，证明文件可读且是有效的 ELF 文件
```

4. **Exec 失败原因**:
```c
execve("/musl/basic/brk", argv, envp);
// 返回 -2 (ENOENT)，因为文件没有执行权限
```

## 技术细节

### 为什么会出现这个问题？

1. **镜像创建时的问题**: 测试镜像 `sdcard-rv.img` 在创建时，所有文件都被赋予了 0000 权限
2. **EXT4 文件系统保留了这些权限**: EXT4 文件系统正确地读取和保留了这些错误的权限
3. **Exec 正确地拒绝执行**: Exec 系统调用正确地检查了权限，拒绝执行没有执行权限的文件

### 为什么 chmod 不工作？

尝试使用 `chmod -R 755 /musl/` 修复权限失败：
- **错误信息**: "chmod: /musl/: Invalid argument"
- **返回码**: 0x100 (失败)

原因：`sys_fchmodat()` 实现不完整

```c
// src/syscall/sysfile.c 第 752-808 行
uint64 sys_fchmodat(void)
{
    // ... 参数验证 ...
    ip = namei(path);
    if(ip == 0){
        end_op(ROOTDEV);
        return -ENOENT;
    }
    iput(ip);      // ← 仅仅释放 inode，没有实际修改权限！
    end_op(ROOTDEV);
    return 0;      // 返回成功，但实际上什么都没做
}
```

该函数只是：
1. 验证参数
2. 查找文件
3. 返回成功

**但没有实际修改文件权限**。

## 解决方案

### 方案 1: 重建镜像（推荐）

重新编译测试程序并创建新的镜像文件，确保文件有正确的权限。

#### 步骤：

1. **进入测试仓库目录**:
```bash
cd 测试仓库/testsuits-for-oskernel/basic
```

2. **清理并重新编译**:
```bash
make clean
make ARCH=riscv64
```

3. **检查生成的文件权限**:
```bash
ls -l user/build/riscv64/
# 确保文件有 0755 权限
```

4. **重新创建镜像**:
```bash
cd ../..
make sdcard-rv.img
```

5. **压缩镜像**:
```bash
xz -k sdcard-rv.img
```

6. **复制到项目目录**:
```bash
cp sdcard-rv.img.xz /path/to/xv6-lab/
cd /path/to/xv6-lab/
xz -d sdcard-rv.img.xz
```

### 方案 2: 实现完整的 fchmodat（中等难度）

修改 `src/syscall/sysfile.c` 中的 `sys_fchmodat()` 函数，添加实际修改权限的代码。

#### 需要实现的功能：

```c
uint64 sys_fchmodat(void)
{
    // ... 现有的参数验证代码 ...

    if(ip == 0){
        end_op(ROOTDEV);
        return -ENOENT;
    }

    // 添加：实际修改权限
    if(ext4_mode){
        // 调用 EXT4 文件系统的 chmod 函数
        int ret = ext4_mode_set(ip->ext4_path, mode);
        if(ret < 0){
            iput(ip);
            end_op(ROOTDEV);
            return -EIO;
        }
    } else {
        // FAT32 文件系统不支持权限
        iput(ip);
        end_op(ROOTDEV);
        return -ENOTSUP;
    }

    iput(ip);
    end_op(ROOTDEV);
    return 0;
}
```

但问题是：**lwext4 库可能没有提供 `ext4_mode_set` 函数**，需要查阅 lwext4 文档或实现该功能。

### 方案 3: 手动修复镜像（临时方案）

在 Linux 主机上挂载镜像并修复权限：

```bash
# 解压镜像
xz -d -k sdcard-rv.img.xz

# 创建挂载点
mkdir -p mnt

# 挂载镜像
sudo mount -o loop sdcard-rv.img mnt

# 修复权限
sudo chmod -R 755 mnt/musl/
sudo chmod 755 mnt/musl/lib/*.so*

# 卸载
sudo umount mnt

# 压缩
xz sdcard-rv.img
```

### 方案 4: 内核绕过权限检查（不推荐）

在 exec 或文件打开时绕过权限检查，仅用于开发/调试：

修改 `src/proc/exec.c` 或文件系统代码，对 `/musl/` 目录下的文件不检查执行权限。

**注意**: 这会降低系统安全性，仅适合调试。
